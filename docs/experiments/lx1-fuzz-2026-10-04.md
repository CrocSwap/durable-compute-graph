# LX1 dispute fuzz campaign (2026-10-04)

Generated-scenario fuzzing of LX1 disputes on tag 227 (subs 23 midpoints, 24
pick, 25 opening with constants, 26 OUTPUT), native ProgramTest, against the
Python reference (`python/dcg/disputes_v21/lx.py`, toy `lx_toy.py`).

## Harness

- Generator: `scripts/disputes_v21_lx_fuzz.py --seed S --count N [--extreme]`
  writes plays to `/private/tmp/dcg-lxfuzz/` (never into the repository).
  Play `i` of seed `s` depends only on `(s, i)`; `--only i` regenerates one.
  Each play randomizes the toy (positions 1-12, window 1-4, h0, weights on
  in about 60%), k (1 to positions+2), arity (2-16), the template's k bounds
  and max positions, the fault (a slot altered after a coordinate: bumped,
  cleared, odd-length bytes or a random value; or, for weighted toys, an
  executor that used another value in WEIGHTS0 or WEIGHTS2), the role order,
  and the challenger's pair and picks (honest, or any choice the reference
  accepts). About 10% are OUTPUT claims (true or false claims over an honest
  or lying run). Expected rulings come from the reference. Each play carries
  structured malformed openings (value, length, clear, dropped, extra or
  moved slots, sibling changes, and constant chunk, path, digest, count and
  order changes), each checked to be refused by the reference.
- Program test: `lx_fuzz_plays_rule_like_python` (ignored) in
  `crates/dcg-program/tests/disputes_v21_lx.rs`. For every play it builds a
  template and run from the play's params, constants root, arity and bounds,
  plays it, and asserts the terminal coordinate, the ruling, the bond
  movement and the run status. Before the good opening it submits the
  structured malformed openings plus two single-byte flips and one
  truncation of the good bytes, and asserts each is refused with the
  dispute, the run and both parties' lamports unchanged.
- Run: `LX_FUZZ_PLAYS=<files> LX_FUZZ_JOBS=8 <test binary> --ignored lx_fuzz`,
  four processes at a time, `CARGO_TARGET_DIR=/private/tmp/dcg-lxfuzz-target`.
  With `LX_FUZZ_PLAYS` set, `send` reuses the latest blockhash and adds a
  per-transaction compute-unit price (payer only) instead of waiting for a
  new blockhash per transaction.
- Planted checks: a play file with one flipped ruling fails; a play whose
  "malformed" list contains the good opening fails.

Coverage of seeds 100-129 (from the play files): 5,373 state disputes and
627 OUTPUT claims; 1,655 weight substitutions; 1,091 terminal openings that
read constants; 3,157 with an arbitrary pair and 2,144 with arbitrary picks.
Rulings by order: executor lies 1,048 C and 1,668 E (an E where the fault
did not reach the disputed transition or the challenger chose badly);
challenger lies 2,657 E and no C.

Wall time: about 23 minutes of program runs for the 6,000 plays (about
0.2 s a play with four processes); generation about 1 s per 200 plays.

## Disagreement: toy start overflows on large h0 (native)

Reproduction:

```sh
PYTHONPATH=python python3 scripts/disputes_v21_lx_fuzz.py --seed 901 --only 116 --extreme
LX_FUZZ_PLAYS=/private/tmp/dcg-lxfuzz/plays-901-x-only116.json \
  cargo test -p dcg-program --features graph-v21,test-kernel --test disputes_v21_lx -- --ignored lx_fuzz
```

The play: toy with positions 1, window 4, h0 = i64::MAX, weights on; the
executor used another WEIGHTS0[6] (not read at position 0), k = 1, arity 2.
The dispute ends at coordinate 0 (`p0.start`), which the executor computed
honestly. The reference rules E. The native program panics in the
test-kernel toy's `apply` (`crates/dcg-program/src/disputes_v21_lx.rs:649`,
`3 * dec(r[0])`, an unchecked multiply: "attempt to multiply with
overflow"), the opening fails with `ProgramFailedToComplete`, and an honest
executor could not answer and would lose at its deadline. First seen at seed
900 index 15 (h0 = -2^62).

Scope: the registered toy machine only (`test-kernel`). The Python toy
computes with unbounded integers; the Rust toy uses an unchecked multiply
then checked additions. In SBF builds the workspace release profile sets
`overflow-checks = false`, so the multiply wraps; since 2^31 divides 2^64,
the wrapped value is the same mod 2^31, and agreement should hold unless the
later `checked_add` overflows (designed, not tested). Not changed here.
Per the campaign rule, the extreme class stopped at this first
disagreement; seeds 901-904 were not run.

## Not tested

- SBF (`V21_SBF=1`) and live validators; native ProgramTest only.
- The extreme class beyond the first failure.
- Timeouts, moot, settlement and closes on generated plays (the existing
  golden tests cover them); OUTPUT plays always use nonce 3 and a fresh run.
- Machines other than the toy; positions above 12.
